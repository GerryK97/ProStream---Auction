1. APPLICATION OVERVIEW
================================================================================

WHAT IS PROSTREAM?
------------------
ProStream Auction Management System is a professional, full-featured platform
for conducting live cricket/sports player auctions with real-time broadcasting
capabilities. Designed for tournament organizers, franchises, and production
teams who need to run seamless auctions with professional-grade streaming
overlays.

PRIMARY PURPOSE
---------------
• Conduct real-time player auctions with live bidding
• Manage tournaments, teams, and player databases
• Generate professional broadcast overlays for OBS/streaming
• Track budgets, bids, and auction history in real-time
• Provide synchronized data across all devices and screens

USER TYPES AND ROLES
--------------------

1. ADMIN
   - Full system access
   - Manage all users, tournaments, teams, and players
   - Access all features without restrictions
   - User management and approval

2. TOURNAMENT MANAGER
   - Manage assigned tournaments
   - Control auction flow (start/stop/restart)
   - Manage players and teams for their tournaments
   - Access auction control panel

3. MASTER DATA MANAGER
   - Manage master player and team databases
   - Create, edit, and delete master data
   - Import/export player and team data
   - Cannot manage tournaments or run auctions

4. TEAM MANAGER
   - View assigned team information
   - Monitor team budget and purchases
   - Limited access to auction viewing

5. PLAYER
   - View player profile information
   - Limited system access

6. AUDIENCE
   - View-only access (when approved)
   - Requires admin approval after registration

A. TOURNAMENT MANAGEMENT
--------------------------------------------------------------------------------
Location: /manage/tournaments

CREATING TOURNAMENTS
--------------------

PROCESS:
1. Navigate to Management Dashboard → Tournaments
2. Fill out tournament creation form:

   BASIC INFORMATION:
   • Tournament Name (required) - e.g., "IPL 2025"
   • Budget Per Team (required) - Total money each team receives
   • Squad Size (required) - Number of players per team
   • Base Price Per Player (required) - Minimum bid amount
   • Tournament Logo (optional) - Upload image via Cloudinary

3. ADVANCED: PLAYER CLASSES (Optional Feature)

   Enable "Player Classes" checkbox to activate

   OPTIONS:
   • Load Defaults: Pre-populate with Icon, Platinum, Gold, Silver, Bronze
   • Add Custom Classes: Define your own classification system

   FOR EACH CLASS:
   • Code (required) - 1-10 characters, unique identifier (e.g., "ICO", "PT")
   • Name (required) - Display name (e.g., "Icon Player")
   • Base Price (optional) - Overrides tournament base price for this class
   • Color (required) - Hex color picker for visual identification
   • Icon (optional) - 1-2 character emoji/symbol for badges
   • Order (required) - Determines display sequence (1, 2, 3, etc.)

4. BASE PRICE STRATEGY (When player classes enabled):
   • Tournament Level: All players use same base price
   • Player Class Based: Each class has its own base price

5. Click "Create Tournament"

TOURNAMENT STATUS WORKFLOW
---------------------------
Draft → Setup → Live → Stopped → Completed → Archived

STATUS DEFINITIONS:
• Draft: Initial creation state
• Setup: Ready for team/player assignment
• Live: Auction is actively running
• Stopped: Auction paused temporarily
• Completed: All players sold
• Archived: Tournament archived for historical records

EDITING TOURNAMENTS
-------------------
1. Click edit icon (pencil) on existing tournament
2. Modify any tournament settings:
   - Basic information
   - Budget, squad size, base price
   - Player classes (add/remove/modify)
3. Click "Save Changes"

DELETING TOURNAMENTS
--------------------
1. Click delete icon (trash)
2. Confirm deletion
3. WARNING: All associated data is permanently deleted:
   - Teams registered in tournament
   - Players registered in tournament
   - Auction state and history
   - Sold player records

TOURNAMENT LIST VIEW
--------------------
DISPLAY INFORMATION:
• Tournament logo thumbnail
• Tournament name
• Status badge (color-coded)
• Budget per team (formatted currency)
• Squad size (number of players)
• Base price per player
• Edit and delete action buttons

TOURNAMENT FILTERING
--------------------
• Search by tournament name
• Filter by status (All/Draft/Setup/Live/Stopped/Completed/Archived)
• Sort by creation date

-------------------------------
Master Players are global player profiles that can be reused across multiple
tournaments. Creating a master player once allows you to add them to any
tournament without re-entering data.

----------------------------

PROCESS:

   • Player Name - Full name

     - Batsman
     - Bowler
     - All-rounder
     - Wicket-keeper
   • Current Club - Team/franchise name

   OPTIONAL FIELDS:
   • Suggested Class - For tournaments with player classes
   • Career Statistics:
     - Matches Played (number)
     - Total Score (runs)
     - Total Wickets (number)
   • Player Photo - Upload image or enter URL
     - Supports: JPG, PNG, GIF
     - Uploaded to Cloudinary
     - Or paste direct image URL

3. Click "Add Player"
4. Player added to master database
5. Auto-assigned unique Player ID

BULK PLAYER UPLOAD
-------------------

PROCESS:
1. Click "Bulk Upload" button
2. DOWNLOAD TEMPLATE:
   - Click "Download Excel Template"

     * Matches Played (optional)
     * Total Score (optional)
     * Total Wickets (optional)
     * Photo URL (optional)
     * Suggested Class (optional)

3. FILL TEMPLATE:
   - Open in Microsoft Excel or Google Sheets
   - Enter player data row by row
   - Save as .xlsx file

4. UPLOAD FILE:
   - Click "Choose File" button or drag and drop
   - Select filled template
   - Click "Upload Players" button
   - System validates and imports data

5. REVIEW RESULTS:
   - Success count displayed
   - Error count displayed (if any)
   - Duplicate players automatically detected and skipped

-----------------------------

1. Click "+ Add Players" button

3. SEARCH AND FILTER:

     * Player name
     * Position

STARTING THE AUCTION
---------------------

PRE-REQUISITES:
• At least 2 teams registered in tournament
• At least 1 player registered in tournament
• Tournament status: Draft or Setup

PROCESS:
1. Click "Start Auction" button
2. System validation:
   - Checks team count (minimum 2)
   - Checks player count (minimum 1)
   - Verifies tournament status

3. AUCTION INITIALIZATION:
   - Tournament status changes to "Live"
   - Auction state created/initialized:
     * Current Player ID: null
     * Current Bid: 0
     * Winning Team ID: null
     * Current Auction Status: "Pending"
     * History: [] (empty)

4. REAL-TIME BROADCAST:
   - State broadcast via Pusher
   - All connected clients receive update:
     * Auction control panels
     * Overlay displays
     * Monitoring screens

5. Success notification displayed
6. "Go to Auction Control" button appears
7. Auto-redirect option to /auction

OTHER AUCTION CONTROLS:

1. STOP AUCTION
   - Click "Stop Auction" button
   - Tournament status changes to "Stopped"
   - Current state preserved
   - All modifications prevented
   - Can be restarted later

2. RESTART AUCTION
   - Available when status is "Stopped"
   - Click "Restart Auction" button
   - Tournament status changes back to "Live"
   - Previous state restored
   - Bidding can resume

3. ARCHIVE TOURNAMENT
   - Available when auction is completed
   - Click "Archive Tournament" button
   - Tournament status changes to "Archived"
   - Read-only mode
   - Historical record preserved

FINALIZING SALE:

WINNING TEAM SELECTION:
• Dropdown menu showing all registered teams
• Displays:
  - Team logo (small)
  - Team name
  - Current balance
  - Warning if insufficient funds
• Default: First team in list
• Can change before selling
• Required to sell player

SELL PLAYER BUTTON:
• Large, prominent green button
• Text: "Sell Player to [Team Name]"
• Requirements to enable:
  - Current bid > 0
  - Winning team selected
  - Auction status not "Sold"

SALE PROCESS:
1. Click "Sell Player" button
2. Confirmation dialog (optional)
3. System processes sale:

   a. UPDATE PLAYER:
      - Set isSold = true
      - Set finalPrice = current bid
      - Set winningTeamId = selected team
      - Set soldTimestamp = current time

   b. UPDATE TEAM:
      - Decrease current balance by final price
      - Increment players purchased count
      - Add player to team's purchased players array

   c. UPDATE AUCTION STATE:
      - Set current auction status to "Sold"
      - Clear current player
      - Reset current bid to 0
      - Add sale to history array

   d. BROADCAST UPDATE:
      - Pusher event to all clients
      - All overlays update instantly
      - Sale banner appears (if overlay active)

4. Visual feedback:
   - Success message
   - Confetti animation (optional)
   - Player moves to sold list
   - Teams panel updates

5. Auction ready for next player

RESET BUTTON:
• Red button, secondary action
• Text: "Reset"
• Functionality:
  - Clears current auction
  - Returns player to available pool
  - Resets current bid to 0
  - Changes auction status to "Pending"
  - Broadcasts reset via Pusher
• Confirmation required
• Use case: Starting player auction by mistake

UNDO LAST SALE BUTTON:
• Located in Teams/Sold panel (also in center panel)
• Text: "Undo Last Sale"
• Functionality:
  - Reverses most recent sale
  - Restores player to available pool
  - Refunds team budget
  - Decrements team player count
  - Removes from sale history
  - Broadcasts undo via Pusher
• Only available if sales exist
• Confirmation required

    * Yellow: Medium balance
    * Red: Low balance

• MAX BID AMOUNT:
  - Calculated value
  - Formula: current balance - (remaining slots × base price)
  - If last slot: entire balance available
  - Labeled: "Max Bid: XXX"
  - Color-coded based on viability

• PLAYERS PURCHASED:
  - "X / Y" format (e.g., "5 / 25")
  - Progress indicator
  - Color changes when approaching squad size

• WARNING INDICATORS:
  - ⚠️ Insufficient funds for remaining slots
  - 🚫 Cannot afford any more players
  - ✓ Healthy budget status

VISUAL HIGHLIGHTING:
• WINNING TEAM (current auction):
  - Animated border (pulsing)
  - Highlighted background
  - Different shadow/glow effect
  - Stands out from other teams

• LOW BALANCE TEAMS:
  - Yellow/orange tint
  - Warning icon

• FULL SQUAD TEAMS:
  - Green checkmark
  - "Squad Complete" badge
  - Different card style

MAX BID CALCULATION DETAILS:
Example:
- Current balance: ₹50,000,000
- Squad size: 25 players
- Players purchased: 20
- Remaining slots: 5
- Base price: ₹1,000,000
- Max bid = ₹50,000,000 - (5 × ₹1,000,000) = ₹45,000,000

Special case (last player):
- Remaining slots: 1
- Max bid = entire current balance

USING OVERLAYS IN OBS (OPEN BROADCASTER SOFTWARE)
================================================================================

SETUP PROCESS
-------------

STEP 1: GENERATE OVERLAY URL

1. Navigate to Overlay Dashboard (/overlays)
2. Browse available overlays
3. PREVIEW OVERLAY:
   - Click eye icon (View button)
   - Opens fullscreen preview
   - See actual overlay in action
   - Press ESC to close

4. CUSTOMIZE PARAMETERS:
   - Click settings icon (Customize button)
   - Parameter editor opens in table row
   - Adjust all available parameters:
     * Colors (visual color picker)
     * Numbers (slider or input)
     * Toggles (on/off switches)
     * Dropdowns (select options)
     * Text inputs (custom text)
   - Real-time preview of changes (if applicable)
   - "Reset to Defaults" button available

5. COPY URL:
   - Click copy icon (clipboard button)
   - Customized URL copied to clipboard
   - URL includes all parameter values
   - Example: /overlays/teams?layout=horizontal&color=cyan&position=bottom

STEP 2: ADD TO OBS

1. Open OBS Studio application

2. ADD BROWSER SOURCE:
   - Right-click in Sources panel
   - Select "Add" → "Browser"
   - Or click + button → Browser

3. CONFIGURE BROWSER SOURCE:
   - Name: Give descriptive name (e.g., "Team Cards Overlay")
   - URL: Paste copied overlay URL
   - Width: Set to overlay width (from dashboard dimensions)
   - Height: Set to overlay height (from dashboard dimensions)

   EXAMPLE:
   - Name: Team Cards
   - URL: http://localhost:3000/overlays/teams?layout=horizontal&position=bottom
   - Width: 1200
   - Height: 200

4. ADVANCED OPTIONS:
   ✓ Check: "Shutdown source when not visible" (performance)
   ✓ Check: "Refresh browser when scene becomes active"
   - FPS: Set to 30-60 FPS
   - CSS: Optional custom styling
   ✗ Uncheck: "Control audio via OBS"

5. Click OK

6. POSITION AND SCALE:
   - Drag overlay to desired position
   - Use corner handles to scale
   - Hold SHIFT while scaling to maintain aspect ratio
   - Use Edit → Transform for precise positioning

STEP 3: CONFIGURE SETTINGS

BROWSER SOURCE SETTINGS:
• Right-click browser source → Properties
• Adjust URL if needed
• Change dimensions if needed
• Modify custom CSS (advanced)

REFRESH BROWSER:
• Right-click browser source → "Refresh"
• Or toggle visibility off/on
• Use when overlay seems stuck

INTERACT WITH PAGE:
• Right-click browser source → "Interact"
• Opens interactive window
• For debugging only (not typically needed)

STEP 4: REAL-TIME SYNC

• Overlays auto-update via Pusher
• No manual refresh needed
• Changes in auction control panel instantly reflect in overlays
• Typical latency: 100-500ms

• If overlay not updating:
  - Check Pusher connection (green dot in control panel)
  - Refresh browser source
  - Check tournament ID in URL matches active tournament
  - Verify internet connection

BEST PRACTICES
--------------

SCENE ORGANIZATION:
• Create separate scenes for different overlay layouts:
  - "Main Display" - Current player + team cards
  - "Team Overview" - Team cards fullscreen
  - "Player Spotlight" - Premium player card
  - "Ticker Only" - Sold players ticker
  - "Final Summary" - Sold summary overlay

PERFORMANCE OPTIMIZATION:
• Keep browser sources visible for optimal performance
• Use "Shutdown when not visible" for unused overlays
• Limit total number of browser sources (8-12 max)
• Use appropriate FPS (30 FPS usually sufficient)

SCENE TRANSITIONS:
• Add smooth fades between scenes (200-300ms)
• Test transitions before going live
• Create hotkeys for quick scene switching

TESTING:
• Test all overlays before going live
• Verify real-time sync is working
• Check all parameters are correct
• Test on second monitor/device

TROUBLESHOOTING:
• Overlay not showing: Check URL, dimensions, visibility
• No real-time updates: Check Pusher connection, tournament ID
• Performance issues: Reduce FPS, limit browser sources
• Styling issues: Check CSS, browser cache

ADVANCED TIPS:
• Use Studio Mode for preview before switching
• Create scene collections for different tournament types
• Use filters (Color Correction, Chroma Key) for custom looks
• Combine multiple overlays in one scene for complex layouts

-----------------------------

TOGGLE SWITCHES:

DROPDOWN SELECTS:
• Click to open options

TEXT INPUTS:
• Click to focus

SAVING CUSTOM CONFIGURATIONS:
• URL parameters auto-update as you change settings
• Copy new URL after customization
• Save URLs in text file for reuse
• No server-side save (URL is the save)

RESET TO DEFAULTS:
• Click "Reset to Defaults" button
• All parameters return to original values
• Useful if customization goes wrong

--------------------------------------------------------------------------------
A. REAL-TIME UPDATES (PUSHER WEBSOCKET)
--------------------------------------------------------------------------------

TECHNOLOGY
----------
• Service: Pusher Channels
• Protocol: WebSockets (with fallback to HTTP long-polling)
• Cluster: ap2 (Asia Pacific 2)

HOW IT WORKS
------------

1. CONNECTION ESTABLISHMENT:
   • Client connects to Pusher on page load
   • Authentication via public API key
   • Channel subscription based on tournament ID
   • Format: "tournament-{tournamentId}"

2. EVENT BROADCASTING:
   • Server triggers events on state changes
   • Events sent to tournament-specific channel
   • All subscribed clients receive events
   • Sub-second latency (typically 100-500ms)

3. CLIENT HANDLING:
   • Clients listen for specific event types
   • Event data includes full state update
   • Client updates local state
   • React components re-render automatically

EVENTS BROADCAST
----------------

1. auction-state-updated
   • Triggered: Any auction state change
   • Data: Complete AuctionState object
   • Includes:
     - currentPlayerId
     - currentBid
     - winningTeamId
     - currentAuctionStatus
     - history array

2. player-selected
   • Triggered: When player selected for auction
   • Data: Player object + auction state
   • Updates:
     - Current player display
     - Player removed from available list

3. bid-placed
   • Triggered: When new bid placed
   • Data: New bid amount
   • Updates:
     - Current bid display
     - All bid-related overlays

4. player-sold
   • Triggered: When player sold to team
   • Data:
     - Player object (with sale info)
     - Team object (with updated balance)
     - Final price
   • Updates:
     - Sold players list
     - Team balances
     - Team player counts
     - Auction state reset

5. auction-status-changed
   • Triggered: Tournament status change (Live/Stopped/etc.)
   • Data: New status
   • Updates:
     - Status indicators
     - Available controls

6. team-updated
   • Triggered: Team data change
   • Data: Updated team object
   • Updates:
     - Team balances
     - Player counts

CHANNELS
--------

TOURNAMENT CHANNEL:
• Format: "tournament-{tournamentId}"
• Private: No (public channel)
• Subscribed by:
  - Auction control panels
  - All overlay pages
  - Monitoring dashboards

CONNECTION MONITORING
---------------------

INDICATORS:
• Green dot: Connected and subscribed
• Red dot: Disconnected
• Status text: "Connected" or "Disconnected"

AUTO-RECONNECT:
• Exponential backoff retry strategy
• Retry intervals: 1s, 2s, 4s, 8s, 16s, 32s (max)
• Continues indefinitely until connected

MANUAL RECONNECT:
• "Reconnect" button available when disconnected
• Forces immediate reconnection attempt

SYNC GUARANTEES
---------------

• All connected clients see same state within 100-500ms
• Conflict resolution: Server state is source of truth
• Last-write-wins strategy for concurrent updates
• Optimistic UI updates with server confirmation

USER BENEFITS
-------------

1. MULTIPLE USERS:
   • Multiple users can view auction simultaneously
   • All see same data in real-time
   • No conflicts or race conditions

2. AUTOMATIC OVERLAY SYNC:
   • Overlays in OBS update automatically
   • No manual refresh needed
   • Perfect sync with auction actions

3. ALL DEVICES SYNCHRONIZED:
   • Desktop, laptop, tablet, phone
   • All show identical state
   • Seamless multi-device experience

4. INSTANT FEEDBACK:
   • Bid placed → All clients see immediately
   • Player sold → All overlays update
   • Status change → All users notified

THEME TOGGLE
------------

LOCATION:
• Navigation bar (header)
• Icon: Sun (light mode) / Moon (dark mode)

FUNCTIONALITY:
1. User clicks theme toggle button
2. JavaScript toggles theme class on <html> element
3. CSS variables update based on class
4. Preference saved to localStorage
5. All components update instantly (no page reload)

PERSISTENCE:
• Key: "theme"
• Value: "dark" or "light"
• Loaded on page load
• Persists across sessions

CODE EXAMPLE:
```javascript
const toggleTheme = () => {
  const currentTheme = localStorage.getItem('theme') || 'dark';
  const newTheme = currentTheme === 'dark' ? 'light' : 'dark';
  document.documentElement.classList.toggle('light-mode');
  localStorage.setItem('theme', newTheme);
};
```

7. TROUBLESHOOTING & SUPPORT
================================================================================

COMMON ISSUES
-------------

1. OVERLAYS NOT UPDATING IN REAL-TIME

SYMPTOMS:
• Overlays show stale data
• Bids not reflecting in OBS
• Player selection not visible

SOLUTIONS:
① Check Pusher connection in auction control panel
   - Look for green dot (connected) vs red dot (disconnected)
   - If red, wait for auto-reconnect or click manual reconnect

② Verify tournament ID in overlay URL matches active tournament
   - Check URL parameter: ?tournament=xxx
   - Compare with tournament ID in auction setup

③ Refresh browser source in OBS
   - Right-click browser source → Refresh
   - Or toggle visibility off/on

④ Check internet connection
   - Ensure stable connection on all devices
   - Check firewall isn't blocking WebSocket connections

⑤ Verify Pusher credentials in .env.local
   - NEXT_PUBLIC_PUSHER_KEY must be set
   - NEXT_PUBLIC_PUSHER_CLUSTER must be set
   - Restart dev server after adding credentials

2. IMAGES NOT LOADING

SYMPTOMS:
• Player photos show broken image icons
• Team logos not visible
• Tournament logos missing

SOLUTIONS:
① Verify Cloudinary credentials
   - Check CLOUDINARY_CLOUD_NAME in .env.local
   - Check CLOUDINARY_API_KEY in .env.local
   - Check CLOUDINARY_API_SECRET in .env.local

② Check image URLs in database
   - Open browser console
   - Look for 404 errors on image URLs
   - Verify URLs are accessible

③ Use fallback placeholder
   - System should auto-fallback to placeholders
   - If not, check console for JavaScript errors

④ Re-upload images
   - Delete broken image
   - Upload new image via upload button

3. LOGIN NOT WORKING

SYMPTOMS:
• "Invalid credentials" error
• Login button not responding
• Redirect loop

SOLUTIONS:
① Verify username and password correct
   - Username is case-sensitive
   - Password must match exactly

② Check account status
   - Contact admin to verify account is Active
   - Audience accounts require admin approval

③ Clear browser cache and cookies
   - Hard refresh: Ctrl+Shift+R (Windows) or Cmd+Shift+R (Mac)
   - Clear localStorage: Open DevTools → Application → Storage → Clear

④ Check MongoDB connection
   - Verify MONGODB_URI in .env.local
   - Ensure database is accessible

⑤ Check JWT secret
   - Verify NEXTAUTH_SECRET in .env.local
   - Restart server after changing

4. AUCTION WON'T START

SYMPTOMS:
• "Start Auction" button disabled or errors
• Validation errors

SOLUTIONS:
① Verify minimum requirements met:
   - At least 2 teams registered ✓
   - At least 1 player registered ✓
   - Tournament status is "Draft" or "Setup" ✓

② Check tournament status
   - Navigate to /manage/tournaments
   - Verify tournament is not already "Live"
   - If wrong status, edit tournament to reset

③ Check for database connection issues
   - Look for error messages in browser console
   - Check server logs for database errors

④ Refresh page and try again
   - Sometimes state can be stale
   - Hard refresh browser

5. PLAYER ALREADY IN TOURNAMENT ERROR

SYMPTOMS:
• Cannot add player to tournament
• "Player already exists" error

SOLUTIONS:
① Check Registered Players panel
   - Player may already be in list
   - Use search to find player

② Remove player if duplicate
   - Click remove button on existing player
   - Re-add with correct details

③ Check player number assignment
   - System auto-assigns sequential numbers
   - If gap in numbers, this is normal

6. TEAM BUDGET CALCULATION INCORRECT

SYMPTOMS:
• Team balance shows wrong amount
• Max bid calculation seems off

SOLUTIONS:
① Verify initial budget set correctly
   - Check tournament settings
   - Initial budget should match tournament budget per team

② Check all sold players for team
   - Sum of final prices should equal spent amount
   - Remaining balance = initial - spent

③ Use "Undo Last Sale" if sale was error
   - This will refund team budget
   - Then re-sell correctly

④ Manually verify calculation
   - Export data to Excel
   - Calculate manually to compare

7. BROWSER SOURCE BLANK IN OBS

SYMPTOMS:
• OBS shows blank screen for overlay
• No content visible in browser source

SOLUTIONS:
① Check URL is complete and correct
   - Should start with http://localhost:3000 (dev)
   - Should include full path (/overlays/...)
   - Should include all parameters

② Verify width and height set correctly
   - Match overlay dimensions from dashboard
   - Not too small (minimum 100×100)

③ Check browser source settings
   - FPS should be 30-60
   - "Shutdown when not visible" may cause issues (uncheck to test)

④ Interact with page to debug
   - Right-click browser source → Interact
   - Check for JavaScript errors in console

⑤ Restart OBS
   - Close and reopen OBS
   - Sometimes cache issues resolved this way

8. PERMISSION DENIED / UNAUTHORIZED

SYMPTOMS:
• "You are not authorized" message
• Redirect to /auth/unauthorized

SOLUTIONS:
① Verify user role
   - Check with admin what role assigned
   - Some features require specific roles

② Check tournament assignment
   - Tournament Managers must be assigned to tournament
   - Contact admin to assign

③ Re-login
   - Logout and login again
   - Token may have expired

④ Contact admin
   - Request role change if needed
   - Request tournament assignment

9. BULK UPLOAD FAILING

SYMPTOMS:
• Excel upload shows errors
• Some rows import, others fail

SOLUTIONS:
① Download template again
   - Use latest template
   - Don't modify column headers

② Check data format
   - Position must be exact: Batsman, Bowler, All-rounder, Wicket-keeper
   - Numbers must be numbers (not text)
   - Required fields must be filled

③ Remove special characters
   - Avoid emoji in names
   - Use standard ASCII characters

④ Upload smaller batches
   - Instead of 100 players, try 20 at a time
   - Easier to identify problematic rows

⑤ Check error report
   - System shows which rows failed and why
   - Fix those specific rows and re-upload

10. PERFORMANCE ISSUES / LAG

SYMPTOMS:
• Slow page loads
• Auction control panel laggy
• Overlays stuttering

SOLUTIONS:
① Check internet speed
   - Minimum 10 Mbps recommended
   - Test at speedtest.net

② Reduce number of browser sources in OBS
   - Maximum 8-12 recommended
   - Hide unused overlays

③ Lower OBS FPS
   - 30 FPS sufficient for overlays
   - 60 FPS only if needed for smooth animations

④ Close unused browser tabs
   - Each overlay page uses resources
   - Close tabs not actively needed

⑤ Check CPU/GPU usage
   - Open Task Manager (Windows) or Activity Monitor (Mac)
   - If >80%, close other applications

⑥ Use wired internet connection
   - WiFi can be unstable for real-time updates
   - Ethernet cable recommended for auctioneer
