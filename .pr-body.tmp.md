## Summary

Make the **Sell**, **Quick Bid** and team-selection clicks in the Auction page feel instant. Users were seeing ~400–800 ms of "stuck button" lag because every click waited for the full HTTP + DB + Pusher round-trip before the UI changed.

This branch adds optimistic UI on top of `main`'s recent server-side parallelisation work, so the user sees the new bid/sale immediately while the network round-trip happens in the background.

## What changed

**Client (`src/components/AuctionControlPanel.tsx`):**
- `handleBid` snapshots `auctionState`, dispatches an `OPTIMISTIC_BID` immediately, then reverts via `restoreAuctionState(snapshot)` if the server rejects.
- `handleSell` snapshots the current player + team via `optimisticSell({ teamId, playerId, bid })` (which marks the player sold and deducts the team balance in-memory), reverts via `restoreSell(snapshot)` on failure.
- Console-log spam removed from both handlers — the eventual Pusher event is the authoritative source.

**Pusher hook (`src/hooks/usePusherAuction.ts`):**
- New reducer actions: `OPTIMISTIC_BID`, `OPTIMISTIC_SELL`, `RESTORE_AUCTION_STATE`, `RESTORE_SELL`.
- New helpers exposed: `optimisticBid`, `optimisticSell`, `restoreAuctionState`, `restoreSell` (snapshot-based revert).
- `BID_PLACED` reducer now keeps the same `teams[]` reference when the incoming team isn't in our list, so memoised consumers don't reconcile on every bid.
- Lifecycle logs gated behind a `dlog` helper (silent in production builds).

**Merged with `main`:**
- All of main's auction route work is preserved — atomic `isSold: false` idempotency guard in `/api/auction/sell`, auth + Team-role bid validation in `/api/auction/bid`, class-completion events, etc.
- The hook keeps main's `isRevoked`, `ClassSelected` / `ClassCompleted`, `updatePlayerAndTeams` additions alongside the new optimistic actions.

## Why
Users reported visible lag clicking Sell, the bid amount buttons, and team selection. The lag came from buttons waiting for the full HTTP + DB + Pusher round-trip before any UI feedback. With the snapshot-based optimistic update, the click takes effect in the same frame, and the eventual Pusher event simply confirms the value (or replaces it on a server-side correction).
